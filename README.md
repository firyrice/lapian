# 知识类视频拉片分析工具

输入一个知识类视频，端到端输出拉片分析结果：每个分镜的**口播文字、代表性画面截图、画面描述**。

提供两种用法：**网页服务**（上传视频、选择模型、在线查看结果）和 **CLI**。

## 网页服务（推荐）

```bash
cd ~/lapian
python3 web.py            # 默认 127.0.0.1:8000，可用 --host/--port 调整
```

浏览器打开 http://127.0.0.1:8000 ：拖拽上传视频 → 选择模型 → 开始分析。
任务列表实时展示进度（切块 / 模型分析 x/y / 截帧），完成后点「查看结果」
在线浏览分镜卡片（截图 + 口播 + 画面描述），并可下载 shots.json / report.md。

- 失败的任务可「重试」：中间产物有缓存，断点续跑不重复调模型
- 任务产物存于 `jobs/<任务ID>/`（原视频 + output/），重启服务历史任务仍在
- 同时分析的任务数上限 2（`web.py` 中 `JOB_WORKERS`），超出排队

## CLI

```bash
cd ~/lapian
python3 main.py --input /path/to/video.mp4
# 常用选项：
#   -o 输出目录（默认 output/<视频名>）
#   -m 覆盖模型，如 gemini-3.7-flash（当前网关未部署该模型，默认 gemini-3.1-pro）
#   -v 调试日志
```

## 原理

1. ffmpeg 把视频切成 2 分钟一块（可配置）
2. 每块视频直接发给 Gemini 端到端理解（画面+语音一起），输出分镜列表（起止时间、口播转录、画面描述、代表性画面时间戳）
3. 按代表性时间戳用 ffmpeg 从**原视频**截帧回填
4. 汇总为 `shots.json` + 图文报告 `report.md`

## 修改配置 / Prompt

- `config.yaml`：模型（`models` 为 Web 端可选列表）、块时长、并行数、截图质量等
- `prompts.yaml`：分析 Prompt 全文，改完即生效

## 输出

```
output/<视频名>/          # CLI 输出；Web 服务为 jobs/<任务ID>/output/
├── shots.json        # 最终结构化数据（分镜编号/口播文字/画面截图/画面描述/制作方法/起止时间）
├── report.md         # 图文拉片报告
├── shots/            # 各分镜代表性截图
├── chunks/           # 切分出的视频块（中间产物）
└── chunk_results/    # 各块分析结果缓存（中断重跑自动续）
```

中断后重新执行相同命令即可断点续跑；删除 `chunk_results/` 可强制重新分析。

## 已知事项

- **gemini-3.7-flash 当前在网关上未部署**（报 `no cluster found`），默认用 gemini-3.1-pro；恢复后在 `config.yaml` 改一行即可切换
- **该网关会随机静默丢弃视频载荷**（返回 200 但模型没收到视频，甚至凭空编造分析）。工具内置两道防线：检查 `usage.video_tokens` + 检测"未收到视频"措辞，命中自动重试，已在实测中验证有效
- 模型的分镜边界时间戳存在秒级漂移（2 分钟分块把误差限制在块内）；代表性画面避开过渡帧，截图与描述始终一致
- 恰好横跨切块边界的分镜会拆成相邻两段（分别属于两个块），属预期行为
- **老任务的 `chunk_results/` 缓存里没有 `制作方法` 字段**，重跑会直接命中缓存跳过分析。要拿这个字段，删掉该任务的 `chunk_results/` 再跑
- `制作方法` 让每块输出的 JSON 大幅变长，偶发被截断（工具会自动重问一次）。若某个视频频繁失败，把 `config.yaml` 的 `chunk.length_seconds` 从 120 降到 60
